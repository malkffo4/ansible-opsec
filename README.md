# ansible-opsec

Харденинг VPN-сервера и ноутбука. Спроектировано так,
чтобы прогон на реальный сервер не мог вас из него выкинуть — каждый
плей безопасен до тех пор, пока вы явно не подтвердите следующий шаг.

## 0. Обязательно перед первым прогоном на прод

- **Не закрывайте текущую SSH-сессию к серверу**, пока весь этот README
  не будет пройден до конца и вы не убедитесь, что новый доступ работает.
- Откройте **веб-консоль хостинг-провайдера** (VNC/serial console) в
  соседней вкладке заранее. Это единственный способ попасть на сервер,
  если SSH всё-таки отвалится — держите его под рукой, а не гуглите
  в панике.
- Сначала прогоните всё на `inventory.local.yml` (тестовые VM), и только
  потом — на реальном сервере через `inventory.yml`.

## 1. Подготовка

```bash
sudo dnf up -y
pip install --user ansible-core
ansible-galaxy collection install -r requirements.yml
ansible-galaxy collection install git+https://github.com/dev-sec/ansible-collection-hardening.git
```

Скопируйте `vars/secrets.yml.example` → `vars/secrets.yml` и заполните:
- `secret_ssh_port` — новый порт для SSH (не 22, не совпадает с VPN).
- `extra_allowed_ports` — порты, которые реально слушает Amnezia
  (см. комментарий в файле — как их узнать).
- `ignore_ips` — ваш текущий внешний IP (`curl ifconfig.me`), чтобы
  fail2ban не забанил вас самого во время тестов.

**vars/secrets.yml подключается плейбуком автоматически** (через
`vars_files`) — `-e @vars/secrets.yml` в команде больше не нужен и
не может быть случайно забыт. Если файла нет или он неполный —
плейбук сразу остановится с понятной ошибкой, а не тихо откатится
на дефолты (как было в первой версии — это и стало причиной того,
что VPN-порт не открылся при первом прогоне).

## 2. Тест на локальных VM

```bash
ansible-playbook -i inventory.local.yml site.yml -K
```

Убедитесь, что всё доехало до конца без ошибок, VPN внутри тестовой VM
поднимается, вы можете зайти новым пользователем.

## 3. Прод: первый прогон (создание юзера + харденинг)

```bash
ansible-playbook -i inventory.yml site.yml --private-key ~/.ssh/id_ed25519 --limit servers
```

Обязательно на управляющей машине (вашем ноутбуке) должен стоять
`openssl` (обычно есть из коробки на Fedora/Ubuntu — отдельно ставить
не нужно; в отличие от первой версии, `python3-passlib` больше не
требуется).

Что произойдёт по шагам:

1. **Плей "0. Bootstrap"** — создаёт юзера `user`, переносит ваш текущий
   SSH-ключ из `/root/.ssh/authorized_keys`. root и порт 22 не трогает.
2. **Плей "1. SSH/OS hardening"** — открывает новый порт и порты VPN в
   файрволе, накатывает `os_hardening`, и **останавливается с паузой**:
   вы увидите точную команду для проверки. Откройте **второй терминал**
   и выполните её:
   ```bash
   ssh -p <новый_порт> user@<ip> -i ~/.ssh/id_ed25519
   sudo -l   # должно отработать без запроса пароля
   ```
   Не получилось — жмите `Ctrl+C` в первом терминале. root и порт 22 всё
   ещё живы, ничего не сломано, чините и запускайте плейбук заново.
   Получилось — возвращайтесь в первый терминал и жмите Enter. После
   этого root и порт 22 (для SSH) будут отключены.
3. **Плей "2. custom_env"** — DNS, chrony, fail2ban, zram и т.д.

## 4. После успешного прогона

- Обновите `inventory.yml`: `ansible_port` → значение `secret_ssh_port`,
  `ansible_user` → `user`.
- **Проверьте, что VPN действительно работает** — подключитесь с
  телефона/другого устройства, а не только смотрите `ufw status`.
  Docker (если Amnezia в нём) иногда конфликтует с ufw — см.
  предупреждение в выводе плейбука.
- Когда убедились, что всё стабильно поработало хотя бы день —
  закройте порт 22 окончательно:
  ```bash
  ansible-playbook -i inventory.yml site.yml -e close_old_ssh_port=true --tags firewall
  ```

## Повторные прогоны / только ноутбук

```bash
ansible-playbook -i inventory.yml site.yml --limit laptops -K
```

## Если что-то пошло не так

- SSH не пускает вообще → веб-консоль провайдера → зайти root'ом с
  паролем из `vars/creds_server1.txt` (этот пароль **только** для
  консоли провайдера, по SSH он не работает) → разобраться, что не
  применилось, поправить руками, перезапустить плейбук.
- `vars/creds_*.txt` и `vars/secrets.yml` не коммитятся (см. `.gitignore`)
  — не теряйте их, это единственная копия root-пароля для консоли.
